# 02 需求解读

> 输入：[01-题目详细定义.md](01-题目详细定义.md)（定稿 2026-10-02）。
> 本文档把赛题痛点转译为系统能力，给出带优先级的功能清单（FR）、非功能需求（NFR）与边界。

## 1. 痛点 → 能力转译表

| # | 痛点（题目 §一） | 转译后的系统能力 | 承载模块 |
|---|---|---|---|
| P1 | 票据量大、人工审核效率低 | 文本票据自动解析 → 统一"票面参数卡"，一条命令端到端 | parse / pipeline |
| P2 | 形式审核维度多、标准不一 | 形式合规校核：必填项 / 时间逻辑 / 流程签字 / 票种匹配，规则 JSON 化 | rules / knowledge |
| P3 | 内涵审核依赖资深经验、易漏审 | 内涵校核：安全措施四要素与组织五制覆盖、倒闸"五防"形式化、一致性互证 | rules（check_type 分派） |
| P4 | 结论无依据、审核人对不出来 | 每条结论强制挂 依据{标准号+条号+原文摘录+status}，无出处不得落库 | rules schema 强制字段 |
| P5 | 行业已有落地全闭源、开源无参考 | 全开源 + 内置可复现基准（零 API）+ 自制带真值数据集 | eval / data/generator |
| P6 | 各单位细则差异大 | 规则库外置为 JSON，可按单位增删；类目门控防跨票种误查 | rules / knowledge |

## 2. 功能需求清单（FR）

优先级：P0 = 评测分直接相关（40 分功能 + 20 分任务指标），P1 = 加分项/表现力，P2 = 可选。

| ID | 优先级 | 需求 | 验收方式 | 里程碑 |
|---|---|---|---|---|
| FR-01 | P0 | 票种识别与路由：7 类票样（变电第一/第二种工作票、线路第一/第二种工作票、事故紧急抢修单、变电站/电力线路倒闸操作票） | 单测：每类样例识别正确；无关文本报"无法识别" | M2 |
| FR-02 | P0 | 文本票据解析 → 票面参数卡（字段-值-置信度-证据{区域,原文摘录}），含操作票逐项序列 | 字段级 P/R/F1 基准 ≥0.95 | M2/M4 |
| FR-03 | P0 | 形式合规校核：必填项、时间逻辑（开始<结束、许可落计划区间、终结闭环）、签字流程完整、票种与工作内容匹配 | 规则单测 + 配对数据检出 | M3 |
| FR-04 | P0 | 内涵合规校核：安全措施四要素+组织五制覆盖检查、五防形式化检查、一致性校核（电压等级/双重名称/人员角色/操作项与措施互证） | 植入缺陷配对集检出率/误报率基准 | M3/M4 |
| FR-05 | P0 | 规范知识库三层（原文→条文块→机器可读规则表），每条挂出处+status，待核对条目显式标注 | 台账核对：知识条目 100% 挂出处或"待核对" | M3 |
| FR-06 | P0 | 结论三级分级：合规 / 不合规（低/一般/较大/重大）/ 待人工确认；结论强制依据关联 | 报告样例审查；无依据结论不得出现 | M3 |
| FR-07 | P0 | LLM 兜底（非结构化抽取兜底/别名归一/复核/报告行文），防幻觉三件套（候选行压缩、逐字摘录回验、数值合法性校验），失败降级规则通路 | 缺 API/断网时全功能规则通路可跑（单测 mock） | M4 |
| FR-08 | P0 | CLI 一条命令端到端（parse/check/demo/run） | `powerticket run` 出参数卡+结论 | M5 |
| FR-09 | P0 | docx 报告导出：结论+分级问题清单+逐条证据+整改建议+签署栏 | 报告样例 + 无外链断言 | M5 |
| FR-10 | P0 | Web 面板（免构建）：上传票据→参数卡→校核结论→报告预览；页面 0 外链、断网可演示 | 冒烟（真实上传）+ 静态 0 外链断言 | M5 |
| FR-11 | P0 | 内置基准评测：①解析 F1（生成器真值 vs 解析）②端到端检出率/误报率；零 API 依赖可重复 | 基准脚本退出码+指标落 README | M4 |
| FR-12 | P0 | 数据生成器：固定 seed、7 票种模板、正常/植入缺陷配对集、真值 JSON（expect/also_expect） | `--force` 重跑位级一致（git status 零变化） | M1 |
| FR-13 | P1 | 打印体扫描件 OCR 解析（加分项） | 样例演示 | M5+（可选） |
| FR-14 | P2 | 多票批量/目录模式；知识库可视化锚点（报告↔KG HTML 联动） | 命令演示 | M5+（可选） |

## 3. 非功能需求（NFR）

| ID | 需求 | 落地手段 |
|---|---|---|
| NFR-01 | 可复现：基准零 API 依赖、固定 seed | 生成器 seed 固定；基准纯规则通路 |
| NFR-02 | 断网可演示：Web/报告/可视化 0 外链 | 前端 vendor 本地化；导出物无 http(s) 外链断言 |
| NFR-03 | 双平台：Windows 开发机 + Linux CI | GitHub Actions 矩阵；路径/编码用 pathlib+UTF-8 |
| NFR-04 | Python ≥3.8（本机实测 3.8.8） | 3.8 兼容写法；CI 另测 3.9/3.11/3.13 |
| NFR-05 | 依赖分层：core 零三方依赖，extras 按需 | pyproject optional-dependencies；extras 覆盖真实 import（含 File()→python-multipart 类隐式依赖） |
| NFR-06 | 数据合规：全部虚构自制 | 生成器制造；设备/人名/单位虚构；台账登记 |
| NFR-07 | 测试覆盖失败路径 | 缺文件/坏格式/票种无法识别/依赖缺失降级，均有测试 |
| NFR-08 | 结论纪律：数值与条文结论只来自确定性规则 | LLM 不产出数值结论；规则无出处不落库 |

## 4. 边界与非目标（继承题目 §六，开发期冻结）

- **不做**：SCADA/生产管理系统实时对接；真实电力公司内部数据；移动端 App；手写体 OCR（打印体扫描仅加分项）。
- **品牌隔离**：不复用姊妹项目代码，文档不提其业务领域；仅复用方法论与工程模式。
- **结论纪律**：无出处的规则不得落库、不得以确定语气写进结论。
- **发布边界**：M6 前不对外宣称"可安装/已发布"；tag/release/topics 等对外动作须用户确认。
