# 04 模块详细设计

> M0 定稿骨架版：schema 与接口为本轮**已实现并锁定的 v0.1**；标注（Mx）的部分为计划内容，随里程碑细化为 v0.2+。M2 定稿增补见 §1 参数卡 `safety_measures` 容器。

## 1. 统一中间表示：票面参数卡（TicketCard）v0.1

所有票种解析后统一为此结构；规则引擎只消费它，不接触原文。

```python
Evidence(region, quote)            # 证据：票面区域(header/body/signature/...) + 原文逐字摘录
FieldValue(value, confidence=1.0, evidence=None)   # 字段包装：值-置信度-证据
OperationStep(no, action, evidence=None)           # 操作票逐项序列
SafetyMeasure(no, text, evidence=None)             # 安全措施逐条（M2 定稿：独立容器）
TicketCard(
    ticket_type,                   # 票种代码，见下表
    fields: dict[str, FieldValue], # 通用字段（编号/任务/时间/人员/发令人…）
    operation_sequence: list[OperationStep],
    safety_measures: list[SafetyMeasure],  # M2 定稿：与 operation_sequence 对称、与生成器真值结构镜像
    warnings: list[str],           # 解析告警（丢弃非法值等，可追溯）
)
```

票种代码表（**既定口径**，M2 起全仓统一）：

| 代码 | 票种 |
|---|---|
| `operating` | 变电站倒闸操作票 |
| `line_operating` | 电力线路倒闸操作票 |
| `work_first` | 变电站（发电厂）第一种工作票 |
| `work_second` | 变电站（发电厂）第二种工作票 |
| `line_work_first` | 电力线路第一种工作票 |
| `line_work_second` | 电力线路第二种工作票 |
| `emergency_repair` | 事故紧急抢修单 |

## 2. 解析层（parse）

流程：**清洗 → 票种路由 → 槽位抽取 → 合法性校验 → 参数卡**。

1. `cleaning.normalize_text`：CRLF→LF、去零宽/全角伪空格（M2 扩展：字符定位伪空格、多行聚类）。
2. 票种路由 `detect_ticket_type`：关键词门控（"倒闸操作票"/"第一种工作票"/…），无匹配 → `ParseError("无法识别票种")`；匹配但解析器未注册 → `ParseError("解析器未注册")`（防御分支，7 票种已全注册）。**M2 定稿：顺序门控**——线路专用关键词（电力线路倒闸操作票/电力线路第一·二种工作票）必须排在同款通用关键词之前（子串包含关系，先命中先返回），负例测试锁定。
3. 槽位抽取：每票种一个 parser（`powerticket/parse/<type>.py`，共享骨架在 `common.py`/`operating.py`/`work.py`）；抽取值必须带证据（区域+原文摘录）。**M2 已实现**：7 票种全覆盖；工作票『计划工作时间：自…至…』一行拆 plan_start/plan_end；发令人（dispatcher）抽取；安全措施逐条入 `safety_measures` 容器。
4. 合法性校验：日期/数值格式不合法（含日历越界）即**丢弃该值+记 warnings**，不得带病入卡；时间值统一 ISO（`YYYY-MM-DDTHH:MM`）。

M4 已落地：LLM 兜底抽取走同一参数卡出口——`parse_ticket_with_fallback(text, allow_llm=False, extract_fn=None)`（默认关闭，core 零 API）；**缺失字段不兜底**（缺失是合规信号）；LLM 字段须携带原文逐字摘录（否则不入卡）+ ISO 时间校验 + warnings 留痕；LLM 不可用一律降级纯规则通路（测试锁定）。详见 `powerticket/llm/fallback.py`。

## 3. 规则引擎（rules）

### 规则 JSON schema（**既定口径**，知识库入库格式）

```json
{
  "id": "R-OP-002",
  "name": "操作时间顺序合法",
  "check_type": "time_order",
  "applies_to": ["operating"],
  "basis": {
    "standard": "Q/GDW 1799.1-2013",
    "clause": "…",
    "quote": "…（原文逐字摘录；非空 ⇔ status=已核对）",
    "channel": "…（该条获取渠道）",
    "status": "已核对|待核对"
  },
  "level": "形式合规",
  "risk": "一般",
  "suggestion": "核对操作开始/结束时间填写是否颠倒。",
  "params": {"mode": "interval", "start": "start_time", "end": "end_time"}
}
```

- `basis` 为必填：无出处的规则**不得落库**；`status ∈ {已核对, 待核对}`，待核对不得以确定语气写进结论；quote 非空 ⇔ 已核对（M3 定稿，测试锁定）。
- `applies_to` 为**类目门控**：引擎在**全部** check_type 上先过门控再分派（防跨票种误查，conditional/checklist 分支也不例外）。
- 正式规则库（M3）：`data/knowledge/rules/` 三文件——`rules-form.json`（required_field×7 + process_signature×5）、`rules-time.json`（time_order×19）、`rules-content.json`（ticket_type_match/measure_coverage/five_prevention/consistency×8），共 **39 条**，7 票种全类型覆盖；每条 (basis.standard, basis.clause) 必须解析到 chunks 条文块（三层联动测试锁定）。

### check_type 分派表

| check_type | 校核内容 | 状态 |
|---|---|---|
| `required_field` | 必填项非空 | ✅ M0 已实现 |
| `time_order` | 时间先后逻辑：params.mode 双模式——`interval`（start<end）/ `in_window`（target 落 [start,end]，on_violation=violation|manual）。M3 扩展：许可开始时间落计划区间（R-W?-004）、终结不早于许可（R-W?-005）、终结超计划区间提示延期（R-W?-006，manual 不硬判） | ✅ M3 全量 |
| `process_signature` | 签字链缺环：工作票 issuer/permitor、抢修单 permitor（操作票双签归 required_field，防归因双计） | ✅ M3 |
| `ticket_type_match` | 票种与停电需求匹配：第二种票任务含需停电表述即错配；任务缺失时本类**跳过不产出结论**（缺失归 required_field，防归因双计，M3 定稿） | ✅ M3 |
| `measure_coverage` | 技术措施四要素（停电/验电/接地/标示牌遮栏），直接消费 `card.safety_measures` | ✅ M3 |
| `five_prevention` | 五防形式化检查三口径：no_load_disconnector（拉开隔离开关前须有断开断路器步）/ no_ground_close（合闸前接地线须拆除）/ grounding_after_test（装设接地线前须验电）；序列为空 → 待人工确认 | ✅ M3 |
| `consistency` | 设备双重名称×电压等级互证：同一设备（线名+编号+类型）在任务与操作项中的 kV 标注应一致 | ✅ M3 |

未知 check_type：跳过+warnings 记录（防御性，不让坏规则炸引擎）。

### 风险分级基线（M3 定稿）

required_field=低；time_order/process_signature=一般；ticket_type_match/measure_coverage=较大；five_prevention=重大；consistency=一般。

### 结论模型（Conclusion）

```python
Conclusion(rule_id, name, verdict, risk, basis, evidence, suggestion)
verdict ∈ {"合规", "不合规", "待人工确认"}
risk    ∈ {None, "低", "一般", "较大", "重大"}     # 仅不合规时有值
```

多值/低置信度/待核对依据 → 一律"待人工确认"，不硬判。

## 4. 知识库（knowledge）——M3 已落地

三层：`data/knowledge/raw/`（规范登记卡+官方原文 PDF）→ `chunks/`（条文块，ingest 确定性建块）→ `rules/`（机器可读规则 JSON，见 §3）。

- raw 登记卡：每项规范一张 JSON（standard/title/channel/source_urls/acquisition/overall_status/clauses[]）；
  条文条目挂 `standard+clause+topic+text+quote+channel+status`；**quote 非空 ⇔ 已核对**（仅官方可直连原文可标已核对，
  当前唯一来源：国能发安全〔2023〕22号官方 PDF，已入仓）；查不到原文 → 待核对+登记渠道，不编造、不停摆。
- chunks：`py -m powerticket.knowledge.ingest [--check]` 从 raw 确定性建块（26 条，位级一致常驻测试）。
- 检索接口（**M3 定稿，列入既定口径**）：
  - `KnowledgeBase.load(path=None) -> KnowledgeBase`（默认 chunks.json）
  - `kb.search(query: str, top_k: int = 5) -> list[tuple[dict, float]]`——余弦相似度降序、同分按 chunk_id 升序、零分不返回
  - 分词：汉字相邻二元组 + ASCII 词元，纯 Python，core 零三方依赖
- 三层联动守门：每条规则的 (basis.standard, basis.clause) 必须解析到条文块（test_knowledge.py）。

## 5. 编排与交付（pipeline / report / web，M5 已落地）

- `pipeline.run_pipeline(text) -> {card, conclusions, summary}`：解析→校核→汇总，CLI 与 Web 共用。
- 报告结构（M5 定稿，决策见 06）：元信息 → 结论汇总 → 分级问题清单（按风险等级）→ 逐条证据（含原文摘录，取参数卡证据链 quote 逐字）→ 整改建议 → 签署栏；"待人工确认"独立成节（解析告警一并列入）。章节结构为零依赖纯函数 `report.sections.build_report_sections`，docx 渲染（extras[report] 懒加载）与 Web 预览共用（预览即所得）；**报告无外链**判据 `report.find_external_links` 进测试（无 `<w:hyperlink>` / 无 External 关系 / 正文无 http(s)://）。
- Web（M5 落地，FastAPI extras[web]）：上传 → 参数卡 → 结论 → 报告预览/docx 导出；前端为零依赖内联单页（static/index.html），**页面 0 外链断言**进测试；/docs、/redoc 关闭（Swagger UI 引 CDN），断网可演示。端点：GET /、GET /healthz、POST /api/check（422 友好错误）、POST /api/report-preview、POST /api/report（docx 下载，缺 extras[report] 返 503）。

## 6. 基准评测（eval，M4 已落地，接口定稿）

| 脚本 | 指标 | 口径（M4 定稿，列入既定口径） |
|---|---|---|
| `parse_f1` | 字段级 P/R/F1 | 评测字段集 = truth.fields（remarks 是唯一不入真值的已抽取字段，不计分）；标量逐键对账（错值=FP+FN），列表块（operation_sequence/safety_measures）按位对账（真值缺键视为空表）；微平均聚合 |
| `endtoend` | 检出率 / 误报率 / 判定准确率 | M3 全集精确对账口径：命中 = 非 pass 结论 check_type 集合 == expect∪also_expect；误报 = 正常样例任何非 pass 或缺陷样例多出 check_type；检出率 = 精确命中缺陷样例/28；误报率 = 有误报样例/35（门槛 0）；判定准确率 = 完全正确样例/35 |

- 接口签名（**既定口径**）：`parse_f1.run(samples_dir=None) -> dict`（含 items/precision/recall/f1/gate/per_ticket_type）；`endtoend.run(samples_dir=None, rules_path=None) -> dict`（含 detection/false_positive_rate/accuracy/gate/failures）；两者 `main(argv)` 支持 `py -m powerticket.eval.<script>` 直跑。
- CLI：`py -m powerticket benchmark [--json]` 跑两脚本并判门槛（F1≥0.95、误报 0；未过退出码 1）。
- 实测（2026-10-02，35 份样例）：F1=1.0（463 项 0 误报 0 漏报）、检出率 1.0、误报率 0、判定准确率 1.0。
- 门槛：F1≥0.95、误报 0；零 API 依赖；指标入 README。
