## 2. 数据生成器设计（M1）

- **输入**：票种 × 正常/缺陷注入参数；**输出**：`*.txt` 票据 + `*.truth.json` 真值。
- **真值语义（既定口径）**：注入项记 `expect`（主期望结论）；同一注入隐含的其余结论记 `also_expect`；评测按"文档全部非 pass 集合"对账，避免双计/漏计。
- **缺陷类型清单**（与规则 check_type 对齐）：缺必填字段、时间倒挂、许可时间越界、签字流程缺环、票种与内容错配、安全措施缺项（四要素逐项）、五防违例（逐条）、双重名称/电压等级不一致。
- **已知坑预登记**：①互斥坑——同一参数两处注入打架（如时间倒挂+时间越界同注）需互斥矩阵；②多值封顶——人员/措施条目数封顶防组合爆炸；③先清旧行——重生成前清空输出目录。
- 固定 seed 全量可复现；`--force` 重跑 git status 零变化作为位级一致门。

## 3. 规范知识库数据计划（M3）

核心依据 6 项（查证状态见题目 §四）：GB 26859-2011、GB 26860-2011、Q/GDW 1799.1-2013、Q/GDW 1799.2-2013、二十五项反措 2023 版（国能发安全〔2023〕22号）、DL/T 408-2023。

- 入库渠道 fallback：官方 API > openstd/nea.gov.cn 直连 > 镜像；逐文件校验（魔数/大小）。
- 每条规则/阈值挂 `standard+clause+channel+status`；查不到 → "待核对"+登记渠道，**不编造、不停摆**。
- 搜索通道可能被污染（方法论实录）：摘要一律不采信，只用可直连官方原文核验。
